# ADR-086: Abrir a conexão com o banco numa classe só, lendo o acesso do .env

- **Status:** Aceita
- **Data:** 2026-11-28
- **Autores:** Grupo do projeto (Gilvan Pedro, Sidney Emanuel, Guilherme Scarcela, João Paulo e Dários Suess)

## Contexto

Com o banco (ADR-085), cinco classes de persistência e a sessão precisam abrir conexão com o
MySQL. O endereço, o usuário e a senha do banco mudam de computador para computador, e a
senha do banco não pode ir para o Git. O projeto já lia as chaves das cifras de um `.env` com
a `dotenv-java` (ADR-020).

## Decisão

> Vamos criar a classe `ConexaoBanco`, com um único método `conectar()`, que lê `DB_URL`,
> `DB_USUARIO` e `DB_SENHA` do `.env` e devolve uma `Connection` nova a cada chamada, porque
> assim o acesso ao banco fica num lugar só e cada pessoa do grupo usa o próprio banco sem
> mexer no código.

```env
DB_URL=jdbc:mysql://localhost:3306/EcoCode
DB_USUARIO=root
DB_SENHA=sua_senha_aqui
```

- Os três valores são lidos uma vez, quando a classe carrega (`static final`).
- `conectar()` chama `DriverManager.getConnection(URL, USUARIO, SENHA)`.
- Quem usa abre a conexão num `try-with-resources`, que fecha a conexão, o
  `PreparedStatement` e o `ResultSet` sozinho, mesmo se der erro.
- O `.env.example` ganhou as três linhas, com uma senha de exemplo.

## Alternativas consideradas

### Alternativa 1: Escrever URL, usuário e senha direto no código

- **Prós:** nada para configurar.
- **Contras:** a senha do banco iria para o Git, e cada integrante teria que mudar o código
  para rodar na própria máquina.
- **Por que não foi escolhida:** é o tipo de coisa que o `.env` existe para evitar.

### Alternativa 2: Pool de conexões (HikariCP)

- **Prós:** reaproveita conexões e é mais rápido com muitos acessos.
- **Contras:** mais uma biblioteca e mais configuração.
- **Por que não foi escolhida:** o programa roda no terminal, com uma pessoa de cada vez.
  Quando o Spring entrar, ele já traz o HikariCP.

### Alternativa 3: Uma conexão única aberta no início e usada para sempre

- **Prós:** abre uma vez só.
- **Contras:** se o MySQL fechar a conexão por tempo parado, tudo para de funcionar até
  reiniciar.
- **Por que não foi escolhida:** abrir uma por operação é simples e não tem esse problema.

## Consequências

### Positivas

- Trocar de banco ou de máquina é mexer só no `.env`.
- Nenhuma classe de persistência repete URL, usuário ou senha.

### Negativas

- Abrir uma conexão nova por operação é mais lento que usar um pool.
- Se o `.env` não tiver as três variáveis, o erro só aparece na primeira tentativa de
  conectar.

### Neutras

- O `.env` agora tem as chaves das cifras e os dados do banco.

## Riscos e pendências

- [ ] O `.env.example` ainda descreve a Cifra Afim com `mod 26` e "a diferente de 13". Com o
  ADR-084, o certo é `mod 62` e "a ímpar e diferente de 31".
- [ ] Quando o Spring entrar, passar a URL, o usuário e a senha para o
  `application.properties` (lendo do ambiente), para o Spring montar o pool.
