# ADR-093: Mover as estruturas de dados e os testes para dentro do pacote backend_ecocode

- **Status:** Aceita
- **Data:** 2026-11-28
- **Autores:** Grupo do projeto (Gilvan Pedro, Sidney Emanuel, Guilherme Scarcela, João Paulo e Dários Suess)

## Contexto

O ADR-073 deixou o pacote `Estrutura` direto em `src/main/java`, fora do `backend_ecocode`,
porque as estruturas não dependem do sistema. A classe `Teste` ficava solta no pacote raiz,
ao lado do `Main`. Com o banco, entraram mais quatro classes de teste (ADR-094), e a raiz
começou a encher.

O projeto também ia ficando com dois pacotes de primeiro nível (`backend_ecocode` e
`Estrutura`), o que confunde quem abre o projeto e foge do ADR-039 (todo o código dentro do
pacote raiz).

## Decisão

> Vamos mover o pacote `Estrutura` para `backend_ecocode.Estrutura` e juntar as classes de teste
> no pacote `backend_ecocode.Testes`, porque assim todo o código fica debaixo de um pacote raiz
> só, como pede o ADR-039, e os testes não se misturam com o `Main` e o `Instanciador`.

```text
src/main/java/backend_ecocode/
├── Estrutura/   No, FilaEncadeada, PilhaEncadeada, Grafo, Dijkstra, NoAVL, ArvoreAVL
├── Testes/      Teste, TesteUsuarios, TesteResiduos, TesteSolicitacoes, TestePontosColeta
├── Main.java
└── Instanciador.java
```

- Os `import` passaram de `Estrutura.X` para `backend_ecocode.Estrutura.X`.
- A classe geral de testes passou a ser `backend_ecocode.Testes.Teste`.
- As estruturas continuam sem depender de nenhuma outra classe do sistema.

## Alternativas consideradas

### Alternativa 1: Manter como o ADR-073 deixou

- **Prós:** nenhum `import` para trocar.
- **Contras:** dois pacotes de primeiro nível e a raiz cheia de testes.
- **Por que não foi escolhida:** o grupo preferiu uma árvore de pastas mais fácil de mostrar.

### Alternativa 2: Mover os testes para `src/test/java`, com JUnit

- **Prós:** é o lugar padrão do Maven, e os testes não iriam junto no programa final.
- **Contras:** os testes do grupo são `main` com `[OK]` e `[FALHA]`, não JUnit. Trocar levaria
  tempo.
- **Por que não foi escolhida:** fica como melhoria. Por enquanto, os testes estão dentro do
  código principal.

## Consequências

### Positivas

- Um pacote raiz só, e cada tipo de classe na sua pasta.
- Quando o Spring escanear o `backend_ecocode`, as estruturas e os testes estão lá dentro, sem
  efeito nenhum, porque não têm anotações do Spring.

### Negativas

- Todos os `import` das estruturas mudaram, e os comandos de rodar o teste nos documentos
  também.
- As classes de teste vão junto no programa final.

### Neutras

- Nos ADRs das estruturas (062, 064, 068, 075, 078, 079) o nome já foi trocado para
  `backend_ecocode.Estrutura`. O ADR-073 ficou com o texto original ("pacote `Estrutura`, fora
  do `backend_ecocode`"), porque ele registra justamente a decisão que este ADR muda.

## Riscos e pendências

- [ ] **`TestePontosColeta` está na pasta `Testes/`, mas ainda declara `package backend_ecocode;`.**
  Trocar para `package backend_ecocode.Testes;`. A IDE pode marcar erro até isso ser feito.
