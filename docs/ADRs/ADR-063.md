# ADR-063: Criar a entidade Solicitacao validando as mudanças de status na própria classe

- **Status:** Aceita
- **Data:** 2026-11-24
- **Autores:** Grupo do projeto (Gilvan Pedro, Sidney Emanuel, Guilherme Scarcela, João Paulo e Dários Suess)

## Contexto

O ADR-051 definiu os quatro status de uma solicitação de descarte e quais mudanças fazem
sentido. Faltava a classe que representa a solicitação e decidir onde fica a regra "de qual
status para qual status pode ir".

## Decisão

> Vamos criar a entidade `Solicitacao` com métodos próprios para cada mudança de status, e cada
> método confere se a mudança é permitida antes de alterar o status.

**Campos**

| Campo | Tipo |
| --- | --- |
| `id` | `UUID` (ADR-061) |
| `usuarioId` | `UUID` de quem pediu |
| `residuoId` | `UUID` do resíduo a descartar |
| `status` | Pendente, Em rota, Concluída ou Cancelada |
| data | `LocalDate` da solicitação |

**Mudanças de status**

| Método | De | Para |
| --- | --- | --- |
| `iniciarRota()` | Pendente | Em rota |
| `finalizarRota()` | Em rota | Concluída |
| `cancelarRota()` | Pendente (usuário) ou Pendente e Em rota (gerente) | Cancelada |

- Uma mudança fora da tabela (por exemplo, concluir uma solicitação ainda pendente) lança
  exceção e o status não muda.
- **Exceção à RN04:** o usuário só cancela enquanto está Pendente, mas o **gerente pode
  cancelar também quando já está Em rota**, por exemplo se o coletor não conseguir buscar.
- Existem dois construtores: um para **criar** uma solicitação nova (gera o id, status
  Pendente, data de hoje) e outro para **carregar** uma já salva, recebendo todos os campos
  como estavam.

## Alternativas consideradas

### Alternativa 1: Um `setStatus` livre e as regras no service

- **Prós:** a entidade fica simples.
- **Contras:** qualquer código poderia pular etapas com `setStatus(CONCLUIDA)`.
- **Por que não foi escolhida:** a própria solicitação garante que só passa por mudanças
  válidas, como o `Residuo` já valida os próprios dados (ADR-014).

## Consequências

### Positivas

- Não existe como deixar uma solicitação num estado impossível.
- Os nomes dos métodos dizem o que acontece no mundo real ("iniciar rota").

### Negativas

- O construtor de carregar não passa pelas regras de criação; serve só para dados já salvos.

## Riscos e pendências

- [ ] Conferir o cargo de quem cancela (usuário ou gerente) antes de chamar o `cancelarRota`.
- [ ] Registrar as mudanças de status no log (ADR-052).
