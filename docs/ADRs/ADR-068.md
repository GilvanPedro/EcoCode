# ADR-068: Implementar um grafo genérico com lista de adjacência no pacote Estrutura

- **Status:** Aceita
- **Data:** 2026-11-24
- **Autores:** Grupo do projeto (Gilvan Pedro, Sidney Emanuel, Guilherme Scarcela, João Paulo e Dários Suess)

## Contexto

O Dijkstra (ADR-048) precisa de um grafo com pesos. Como na fila (ADR-062), o projeto
integrador pede que o grupo implemente as estruturas de dados estudadas, em vez de usar uma
biblioteca de grafos pronta.

Há duas formas clássicas de guardar um grafo: **matriz de adjacência** (uma tabela N × N com
o peso de cada par) e **lista de adjacência** (cada vértice guarda só os seus vizinhos).

## Decisão

> Vamos criar a classe genérica `Grafo<T>`, no pacote `Estrutura`, não direcionada, guardada
> como lista de adjacência num `Map<T, Map<T, Double>>`, que recusa peso negativo e laço.

```text
Map<T, Map<T, Double>>
 vértice  ->  { vizinho: peso, vizinho: peso, ... }
```

- O `Map` de fora liga cada vértice aos seus vizinhos; o `Map` de dentro liga cada vizinho ao
  peso da aresta.
- **Não direcionado:** ao adicionar a aresta A–B, ela é gravada em A e em B com o mesmo peso.
- **Peso negativo é recusado**, porque o Dijkstra dá resultado errado com ele.
- **Laço é recusado** (aresta de um vértice para ele mesmo), porque não faz sentido no mapa da
  cidade.
- É **genérico** (`<T>`), como a `FilaEncadeada<T>`. No EcoCode, é usado como `Grafo<Bairro>`
  (ADR-067).

## Alternativas consideradas

### Alternativa 1: Matriz de adjacência (`double[15][15]`)

- **Prós:** consultar o peso entre dois vértices é direto.
- **Contras:** com 15 vértices e 30 arestas, a maior parte das 225 posições ficaria vazia; os
  vértices viram índices numéricos, e é preciso converter bairro em número e de volta.
- **Por que não foi escolhida:** a lista guarda só o que existe e usa o próprio `Bairro` como
  chave.

### Alternativa 2: Lista de objetos `Aresta`

- **Prós:** cada aresta é um objeto fácil de imprimir.
- **Contras:** para achar os vizinhos de um vértice, seria preciso percorrer todas as arestas.
- **Por que não foi escolhida:** o Dijkstra pede os vizinhos de cada vértice o tempo todo.

### Alternativa 3: Biblioteca pronta (por exemplo, JGraphT)

- **Prós:** Dijkstra já incluído.
- **Contras:** não mostra a implementação.
- **Por que não foi escolhida:** o trabalho pede a estrutura feita pelo grupo.

## Consequências

### Positivas

- Os vizinhos de um vértice saem direto do `Map`, que é a operação mais usada pelo Dijkstra.
- As validações de peso e laço impedem erros na montagem antes de chegar ao algoritmo.
- A mesma classe serve para qualquer tipo de vértice.

### Negativas

- Gravar a aresta nos dois sentidos dobra o que é guardado; com 30 arestas, isso não pesa.

### Neutras

- O pacote `Estrutura` agora tem a fila (ADR-062) e o grafo; a AVL (ADR-049) e a pilha
  (ADR-052) devem ir para o mesmo lugar.
