# ADR-077: Achar o ponto de coleta mais próximo rodando o Dijkstra uma vez a partir do bairro do usuário

- **Status:** Aceita
- **Data:** 2026-11-26
- **Autores:** Grupo do projeto (Gilvan Pedro, Sidney Emanuel, Guilherme Scarcela, João Paulo e Dários Suess)

## Contexto

Com o bairro no usuário (ADR-074), o `Dijkstra<T>` pronto (ADR-075) e os pontos de coleta
cadastrados (ADR-076), faltava juntar as três coisas para responder "qual ponto fica mais
perto de mim?". Havia dois caminhos: rodar o Dijkstra uma vez para cada ponto, ou uma vez só
a partir do usuário.

## Decisão

> Vamos criar `pontoMaisProximo(usuario)` no `GerenciarPontoColetaService`, rodando o Dijkstra
> uma única vez a partir do bairro do usuário e escolhendo o ponto cujo bairro tem a menor
> distância, porque uma rodada já dá a distância até todos os bairros.

1. Confere se o usuário foi informado e se tem bairro.
2. Lista os pontos; se não houver nenhum, lança `IllegalStateException`.
3. Roda `new Dijkstra<>(grafo).calcular(usuario.getBairro())` e recebe o mapa de distâncias.
4. Percorre os pontos e fica com o que tem a menor distância até o seu bairro.

- O `Grafo<Bairro>` é montado uma vez pela `GrafoBairros.criar()` no `Instanciador` e entra no
  service pelo construtor (ADR-058).
- Um `Dijkstra` novo é criado a cada chamada, porque ele guarda o estado do cálculo.
- Se dois pontos estiverem no mesmo bairro, ou à mesma distância, fica o primeiro da lista.

## Alternativas consideradas

### Alternativa 1: Rodar o Dijkstra uma vez por ponto de coleta

- **Prós:** cada resposta seria só a distância de um ponto.
- **Contras:** com 5 pontos, 5 rodadas para chegar ao mesmo resultado.
- **Por que não foi escolhida:** desperdício; o Dijkstra já calcula todos os destinos.

### Alternativa 2: Guardar uma tabela pronta com o ponto mais próximo de cada bairro

- **Prós:** resposta instantânea.
- **Contras:** a tabela fica velha quando um ponto é cadastrado ou excluído.
- **Por que não foi escolhida:** com 19 bairros o cálculo já é instantâneo, e mostrar o
  algoritmo rodando é parte do trabalho.

## Consequências

### Positivas

- Uma rodada de O(V²) por consulta, sem nenhum dado extra para manter.
- Cadastrar ou excluir um ponto muda o resultado na hora.

### Negativas

- O resultado devolve só o ponto, sem a distância nem o caminho, que seriam bons para a tela.

### Neutras

- A tabela de `docs/GrafoBairros.md` com o ecoponto mais próximo de cada bairro serve de
  gabarito para os testes.

## Riscos e pendências

- [ ] Avaliar devolver também a distância em km, para a tela "Ponto mais próximo".
- [ ] Se um bairro ficar sem caminho até nenhum ponto (distância infinita), mostrar uma
  mensagem em vez de devolver um ponto inalcançável.
