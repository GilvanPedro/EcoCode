# ADR-075: Implementar o Dijkstra numa classe genérica própria, sem fila de prioridade

- **Status:** Aceita
- **Data:** 2026-11-25
- **Autores:** Grupo do projeto (Gilvan Pedro, Sidney Emanuel, Guilherme Scarcela, João Paulo e Dários Suess)

## Contexto

O ADR-048 escolheu o Dijkstra para achar o ponto de coleta mais próximo, e o ADR-068 criou o
`Grafo<T>`. Faltava decidir onde o algoritmo mora e como ele escolhe o próximo vértice a
visitar. O grafo tem 19 bairros e 40 arestas (ADR-072).

## Decisão

> Vamos criar a classe `Dijkstra<T>` no pacote `Estrutura`, separada do `Grafo<T>`, e escolher
> o próximo vértice percorrendo todos os não visitados, sem fila de prioridade, porque com 19
> vértices isso é rápido e fica mais fácil de explicar.

- O construtor recebe o `Grafo<T>`. O método `calcular(origem)` devolve um
  `Map<T, Double>` com a menor distância da origem até cada vértice.
- O método foi quebrado em partes pequenas:

| Método | O que faz |
| --- | --- |
| `iniciar(origem)` | Põe todos os vértices em infinito e a origem em 0 |
| `maisProximoNaoVisitado()` | Procura, entre os não visitados, o de menor distância; devolve `null` quando acabam |
| `relaxarVizinhos(atual)` | Para cada vizinho, vê se passar pelo atual deixa o caminho mais curto |

- Vértice que não se alcança fica com `Double.POSITIVE_INFINITY`.
- Uma origem que não está no grafo lança `IllegalArgumentException`.
- O custo é O(V²): para cada um dos V vértices, percorre os V para achar o mais próximo.

## Alternativas consideradas

### Alternativa 1: Dijkstra com fila de prioridade (`PriorityQueue`)

- **Prós:** O((V + E) log V), melhor para grafos grandes.
- **Contras:** usa uma estrutura pronta do Java e precisa tratar entradas repetidas na fila.
- **Por que não foi escolhida:** com 19 vértices a diferença não aparece, e a versão simples
  mostra melhor o passo a passo na apresentação.

### Alternativa 2: Colocar o Dijkstra dentro do `Grafo<T>`

- **Prós:** uma classe a menos.
- **Contras:** o grafo passaria a guardar estado do cálculo (distâncias e visitados).
- **Por que não foi escolhida:** o grafo só representa os dados; o algoritmo é outra
  responsabilidade.

## Consequências

### Positivas

- O código do algoritmo segue a explicação do caderno, um passo por método.
- Por ser genérica, a classe funciona com qualquer `Grafo<T>`, não só com bairros.

### Negativas

- Se o grafo crescer muito (centenas de bairros), a versão O(V²) fica lenta.

### Neutras

- A classe guarda distâncias e visitados como atributos, então cada cálculo usa uma instância
  nova (ADR-077).
