# ADR-059: Separar o cadastro aberto de usuários do cadastro feito pelo gerente, e criar a promoção de cargo

- **Status:** Aceita
- **Data:** 2026-11-23
- **Autores:** Grupo do projeto (Gilvan Pedro, Sidney Emanuel, Guilherme Scarcela, João Paulo e Dários Suess)

## Contexto

Pelo ADR-022, ninguém se cadastrava sozinho: só um gerente criava contas. Isso servia para um
sistema interno, mas no app do projeto integrador o cidadão que quer descartar lixo eletrônico
precisa criar a própria conta. Ao mesmo tempo, o gerente continua precisando criar contas da
equipe já com o cargo certo, e trocar o cargo de quem já existe (ADR-053).

## Decisão

> Vamos ter dois caminhos de cadastro no `GerenciarUsuariosService`, um aberto a qualquer pessoa
> e outro só do gerente, que compartilham a mesma gravação, e um método para o gerente mudar o
> cargo de um usuário.

| Método | Quem usa | Cargo do novo usuário |
| --- | --- | --- |
| `cadastro` | Qualquer pessoa | Sempre `USUARIO` |
| `cadastroGerente` | Só gerente | O cargo que o gerente escolher |
| `salvarNovoUsuario` (privado) | Os dois acima | Faz as checagens de CPF e e-mail repetidos (ADR-057), cifra a senha e grava |
| `promoverUsuario(Usuario gerenteLogado, cpf, novoCargo)` | Só gerente | Troca o cargo do usuário daquele CPF |

- O `CargoUsuario` ganhou o valor `USUARIO`, o nível mais baixo (ADR-053).
- O `cadastro` aberto **não recebe cargo**: não existe como uma pessoa se cadastrar já como
  gerente.
- O `salvarNovoUsuario` é `private`, então só o próprio service chama. A lógica de gravar fica
  num lugar só, e os dois cadastros não se repetem.
- O `promoverUsuario` confere se quem chama é gerente (RN08) e se o CPF não é o do próprio
  gerente (RN09).

## Alternativas consideradas

### Alternativa 1: Um único `cadastrar` recebendo o cargo

- **Prós:** um método só.
- **Contras:** o cadastro aberto teria que ignorar ou recusar o cargo recebido; fácil de
  esquecer a checagem e deixar alguém se cadastrar como gerente.
- **Por que não foi escolhida:** dois métodos deixam claro quem pode o quê.

### Alternativa 2: Promover pela edição comum do usuário

- **Prós:** nenhum método novo.
- **Contras:** misturaria uma ação restrita ao gerente com a edição que o próprio usuário faz.
- **Por que não foi escolhida:** troca de cargo tem regras próprias e vai para o log.

## Consequências

### Positivas

- O cidadão cria a própria conta; a equipe é criada pelo gerente.
- Gravação e checagens num método privado, sem código repetido.

### Negativas

- O cadastro aberto permite contas falsas; não há confirmação de e-mail.

## Riscos e pendências

- [ ] Registrar a troca de cargo no log de auditoria quando o log existir (RN10, ADR-052).
- [ ] Ainda não há tela para esses métodos; eles são testados direto pelo service (ADR-055).
