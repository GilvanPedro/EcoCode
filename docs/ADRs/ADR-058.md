# ADR-058: Montar os objetos na classe Instanciador, com injeção de dependência pelo construtor

- **Status:** Aceita
- **Data:** 2026-11-24
- **Autores:** Grupo do projeto (Gilvan Pedro, Sidney Emanuel, Guilherme Scarcela, João Paulo e Dários Suess)

## Contexto

O ADR-040 deixou registrado que existiam várias cópias do mesmo repository: cada service
criava o seu com `new`, e a tela e o `Main` criavam services próprios. Cada cópia carregava o
arquivo na memória e gravava por cima das outras. A pendência era trocar o `new` pela injeção
do Spring, mas o grupo decidiu terminar o back-end em Java puro antes (ADR-055).

## Decisão

> Vamos criar a classe `Instanciador`, que cria **uma única instância** de cada repository e de
> cada service e entrega cada dependência pelo construtor de quem a usa.

```text
Instanciador
 ├── cria 1 GerenciarUsuariosRepository ──> passa para o GerenciarUsuariosService
 ├── cria 1 GerenciarResiduosRepository ──> passa para o GerenciarResiduosService
 └── ...
```

- Os services não fazem mais `new` de repository: recebem pelo construtor.
- Todo mundo que precisa de um service pega do `Instanciador`, então o sistema inteiro usa os
  mesmos objetos.
- **O Spring continua no `pom.xml`.** Ele não é usado agora, mas vai ser na etapa do front
  (ADR-055). Quando entrar, o Spring passa a fazer o papel do `Instanciador`, e os construtores
  já estão no formato que ele espera.

## Alternativas consideradas

### Alternativa 1: Usar a injeção do Spring já agora

- **Prós:** o framework faz a montagem.
- **Contras:** exige rodar o back-end dentro do Spring numa etapa em que o grupo quer Java puro.
- **Por que não foi escolhida:** fica para quando o front entrar.

### Alternativa 2: Repositories como Singleton (`getInstance()` estático)

- **Prós:** garante uma instância só sem classe extra.
- **Contras:** a dependência fica escondida dentro do código, e atrapalha a troca pelo Spring
  depois.
- **Por que não foi escolhida:** passar pelo construtor deixa claro quem depende de quem, como
  no `Scanner` do ADR-046.

### Alternativa 3: Tirar o Spring do `pom.xml` enquanto não é usado

- **Prós:** build mais rápido.
- **Contras:** teria que ser colocado de volta, com a configuração, daqui a poucos dias.
- **Por que não foi escolhida:** vai ser usado na próxima etapa.

## Consequências

### Positivas

- Resolve as instâncias duplicadas do ADR-040: uma cópia só dos dados em memória.
- A troca para o Spring depois fica quase direta.

### Negativas

- Toda classe nova com dependências precisa ser registrada no `Instanciador`.

## Referências

- Resolve a pendência de injeção do ADR-040. ADR-038 (Spring), ADR-046 (dependência pelo
  construtor), ADR-055 (Java puro primeiro).
- `Instanciador`, `Service/*`, `Repository/*`.
