# ADR-053: Organizar os cargos em níveis e deixar só o gerente alterar cargos, pelo CPF

- **Status:** Aceita
- **Data:** 2026-11-23
- **Autores:** Grupo do projeto (Gilvan Pedro, Sidney Emanuel, Guilherme Scarcela, João Paulo e Dários Suess)

## Contexto

O módulo de usuários tinha só dois cargos, `GERENTE` e `FUNCIONARIO`, e só gerentes
cadastravam (ADR-022). No app do projeto integrador aparecem mais papéis: quem descarta, quem
coleta e quem administra a fila. Também ficou em aberto, desde o ADR-022, como criar o
primeiro gerente.

## Decisão

> Vamos ter cargos em níveis, cada um acessando só as suas funções, e deixar só o gerente
> mudar o cargo de alguém, informando o CPF dessa pessoa.

**Níveis (sugestão do grupo, ainda a fechar)**

```text
Usuário  <  Coletor  <  Administrador  <  Gerente
```

**Regras**

| Regra | Requisito |
| --- | --- |
| Cada cargo acessa só as suas funções | RN05 |
| Só o gerente altera cargo | RN08 |
| Ninguém altera o próprio cargo, nem o gerente | RN09 |
| Toda alteração de cargo vai para o log de auditoria | RN10 |

- O gerente encontra a pessoa pelo **CPF**, que é único (RN01) e é o dado que a pessoa sabe
  informar.
- **Primeiro gerente:** é criado direto no banco, fora do sistema. Assim nenhuma tela precisa
  de uma porta de entrada para criar gerentes.
- O método que faz a troca é o `promoverUsuario` (ADR-059).

## Alternativas consideradas

### Alternativa 1: Manter só gerente e funcionário

- **Prós:** nenhuma mudança no código.
- **Contras:** não separa quem coleta de quem administra, nem o cidadão que só descarta.
- **Por que não foi escolhida:** o app tem papéis diferentes.

### Alternativa 2: Criar o primeiro gerente automaticamente quando não houver usuários

- **Prós:** o sistema funciona logo na primeira execução.
- **Contras:** quem chegar primeiro vira gerente.
- **Por que não foi escolhida:** criar direto no banco é mais seguro.

## Consequências

### Positivas

- Resolve a pendência do primeiro gerente (ADR-022).
- Impedir a mudança do próprio cargo bloqueia o caminho mais simples de alguém se dar poder.

### Negativas

- O enum `CargoUsuario` precisa ganhar novos valores, e as checagens de permissão crescem.
